# V4.1 — Full-Context Enrichment & AI Headlines
### Ethiopia News Aggregation Platform (revision to V4, applied before continuing to V7)

**Scope note:** This is a scoped revision to V4's `enrich.go`, not a new version in the roadmap. It's triggered by real V6 visual review: the AI summary read as too thin/summarized, and event titles were raw truncated post text rather than real headlines. This document defines the fix, references — but does not repeat — `docs/architecture/platform-architecture.md` and `v4-ai-enrichment-spec.md`. **Full-article expansion (fetching and reading the linked website behind a Telegram "see more" post) is explicitly deferred to a future post-MVP version** — this revision only improves what's achievable from Telegram post text already in the database.

---

## 1. What's Wrong, Precisely

1. **`ai_summary` was generated from limited context and capped short (2–4 sentences)**, per the original V4 spec's own scope. Real user review shows this reads as a thin blurb, not a report — even though multiple sources may contain more corroborated detail than a 2–4 sentence cap allows.
2. **`canonical_title` was never AI-generated** — it's raw, truncated text from the *first* post that started the event (a V2-era placeholder, explicitly flagged as a known rough edge back in V2's spec, section 1.2: "this is a known, acceptable rough placeholder"). It was never revisited once V4 added real enrichment, so titles still cut off mid-sentence.

## 2. What This Revision Does — and What It Deliberately Does Not Attempt

**In scope:**
- Enrichment now uses **all `raw_text` from every source in the event**, not one representative post — the AI should have the full corroborated picture across all clustered channels, not a single post's partial framing.
- `ai_summary` becomes a properly structured, multi-paragraph report — length driven by how much corroborated material actually exists across sources, not a fixed short cap. Direct quotes present in source posts are preserved verbatim and attributed (e.g., `"quoted text," per Capital Ethiopia`) rather than paraphrased away.
- A new `ai_headline` field: a complete, grammatically correct, properly-cased headline generated by the same enrichment call — never a truncated fragment.
- Explicit anti-hallucination instruction in the prompt: only report facts and quotes that actually appear in the source texts provided; do not add plausible-sounding detail that isn't there. This is a hard extension of the same principle V4 already established, not a new one.

**Explicitly NOT in scope for this revision** (this is the "for now" boundary you and I agreed on):
- Fetching full article content from links Telegram posts point to ("see more on our website") — that's a future, larger capability (a new ingestion source type, consistent with the architecture doc's "future expansion to RSS/websites" goal) and depends on V1-style ingestion work, not just an enrichment prompt change. Real FT-level depth genuinely requires that future work — this revision gets as close as possible using only what's already ingested.
- Any change to clustering, verification, or the `needs_review` pipeline (V3/V4's core logic untouched).
- Any frontend redesign beyond rendering the new fields correctly (that's the separate, later design pass).

## 3. Database Changes

New migration `0007_ai_headline.sql`:
```sql
ALTER TABLE news_events ADD COLUMN ai_headline TEXT;
-- Nullable: existing events keep their old canonical_title until re-enriched;
-- re-enrichment (already-existing V4 logic, triggered on new-source-attach or
-- manual backfill) will populate ai_headline going forward.
```
`canonical_title` is **not removed** — it remains as an internal/fallback field (useful if `ai_headline` generation ever fails) but the frontend switches to preferring `ai_headline` when present (1.5).

## 4. Prompt/Logic Changes (`enrich.go`)

- Query change: fetch `raw_text` from **all** `event_sources`-joined `raw_posts` for the event, not the founding post alone.
- Prompt restructure, roughly:
  > "You are a professional news reporter. Using ONLY the facts present in the source texts below (from N different channels reporting the same event), write a complete, well-organized news report in flowing prose — multiple paragraphs if the material supports it. Preserve any direct quotations verbatim, attributed to their source. Do not invent, assume, or add any fact not present in the provided texts. Do not present disconnected fragments — write a coherent narrative. Then provide: a complete, properly-formed headline (not truncated, ending on a full thought); a single category from [list]; named entities."
- Response schema gains `ai_headline` alongside the existing `ai_summary`, `category`, `entities`.
- Same `processing_audit` requirement as before (V4 spec 1.4) — this is still one audited call, extended in scope, not a new untracked call.
- Same stability-window re-enrichment trigger as V4 already built (event re-enriched when a materially new source attaches) — now naturally more valuable, since a later source can add real corroborating detail the fuller-report style can actually use.

## 5. Frontend Changes (`web/`)

- `EventCard` and `EventDetail` render `ai_headline` when present, falling back to `canonical_title` only if `ai_headline` is null (not-yet-re-enriched older events).
- `EventDetail`'s summary rendering updates from a single short paragraph to properly rendering multiple paragraphs (respecting the AI's paragraph breaks, not collapsing everything into one block).
- The AI-generated-content label (V4/V6's non-negotiable transparency requirement) still applies to both `ai_headline` and `ai_summary` — a longer, better-written report is still generated content and must still be labeled as such. This requirement does not weaken just because the output reads more like real journalism now — if anything it matters more, since better-written output is easier to mistake for original reporting.

## 6. Testing

- A test using a real multi-source cluster (e.g., a past event with 2+ real sources) confirming: the new `ai_summary` incorporates facts from *all* sources, not just the founding post; a direct quote present in a source is preserved and attributed; `ai_headline` is complete (not truncated, ends on a full thought).
- A hallucination-guard test: construct a source set missing a specific plausible-sounding detail, confirm the AI does not introduce it — this is the test that actually proves the "don't blindly trust AI" principle holds under the new, more permissive-sounding prompt.
- Frontend test confirming `ai_headline` is preferred when present, `canonical_title` used as fallback otherwise, and the generated-content label still renders on both fields.

## 7. Acceptance Criteria

- [ ] Migration `0007_ai_headline.sql` applied.
- [ ] A real re-enriched multi-source event, reviewed by you, reads as a genuine multi-paragraph report using facts from all its sources — not a short blurb.
- [ ] Direct quotes from real source posts appear verbatim and attributed in at least one real reviewed example.
- [ ] Headlines no longer truncate mid-sentence — verified on multiple real events.
- [ ] Hallucination-guard test passes.
- [ ] Frontend correctly prefers `ai_headline`, falls back gracefully for un-re-enriched events.
- [ ] AI-generated-content label still present and correct on both fields.
- [ ] `processing_audit` still records every enrichment call under the extended prompt.
- [ ] No ingestion, clustering, or verification logic touched.
